Conceito

Testes de Requisitos Não Funcionais

Na Aula 1 levantamos os NFRs. Agora verificamos se a aplicação os cumpre:

Teste de desempenho

A aplicação aguenta 1.000 usuários simultâneos? Qual é a latência média? Há degradação?

Teste de segurança

O sistema rejeita entradas inválidas? Valores negativos, tipos errados, injeção de dados.

Teste de confiabilidade

Os cálculos matemáticos são exatos? Arredondamento correto em moeda?

Teste de usabilidade

Um corretor sem treino técnico consegue gerar um orçamento em menos de 2 minutos?

NFRs não testados são suposições — e suposições não vão para produção.

Desempenho · Locust

Simulando 1.000 Usuários Simultâneos

# pip install locust # locustfile.py from locust import HttpUser, task, between class ImovelUser(HttpUser): wait_time = between(1, 3) # pausa realista entre requisições @task def gerar_orcamento(self): """Simula um corretor gerando um orçamento.""" self.client.post("/gerar", json={ "tipo": "Apartamento", "quartos": 2, "garagem": True, "sem_criancas": False, "parcelas": 3 }) # Rodar: locust -f locustfile.py --users 1000 --spawn-rate 50 # Abre painel em http://localhost:8089
spawn-rate 50 = 50 usuários/segundo até atingir 1.000. Observar quando latência começa a crescer.

(requests com falha)

Throughput mínimo
(requests por segundo)

Latência p95

95% das requisições abaixo de 2s. O p99 pode ser mais alto — e tudo bem.

Taxa de erro

Erros HTTP 5xx indicam bugs sob carga — não é comportamento esperado.

Segurança · Validação de Entradas

Testando Entradas Maliciosas

import pytest from domain.imovel import Apartamento from domain.contrato import Contrato class TestSeguranca: def test_valor_base_negativo(self): """Sistema não pode aceitar aluguel negativo.""" with pytest.raises(ValueError): Apartamento(valor_base=-500) def test_parcelas_acima_do_limite(self): """Contrato parcelado em mais de 5x deve ser rejeitado.""" with pytest.raises(ValueError): Contrato(qtd_parcelas=10) def test_nome_cliente_vazio(self): """Nome em branco não pode gerar orçamento.""" from domain.orcamento import Orcamento with pytest.raises(ValueError, match="nome"): Orcamento(cliente_nome="", cliente_sem_criancas=False, imovel=Apartamento(), taxa_contrato=2000, parcelas_contrato=1)
Validações pertencem ao domínio, não à UI — assim são testáveis sem depender do Streamlit.

Deploy

Publicando no Streamlit Community Cloud

Zero configuração de servidor — deploy em 3 passos:

  • 1. requirements.txt — liste as dependências: streamlit, qualquer lib usada.
  • 2. Push no GitHub — o repositório precisa ser público (ou privado com conta Pro).
  • 3. share.streamlit.io — "New app" → aponte para o repositório e o arquivo app.py.
# requirements.txt streamlit>=1.36.0 pytest>=8.0 # Estrutura mínima do repositório imobiliaria-rm/ ├── app.py # entrada Streamlit (camada UI) ├── domain/ │ ├── imovel.py # Imovel, Apartamento, Casa, Estudio │ ├── contrato.py │ └── orcamento.py ├── tests/ │ └── test_seguranca.py └── requirements.txt

Requisitos de Entrega

📊

Fluxograma Teórico (PDF)

Diagrama da lógica principal — do input do corretor ao CSV gerado. Ferramenta: draw.io, Miro ou papel fotografado.

Repositório público com OOP implementado. Estrutura de camadas obrigatória. README com instruções de execução.

🎥

Vídeo Pitch (4 minutos)

Apresente o problema, a solução e uma demo ao vivo. Mostre o CSV sendo gerado e explique uma regra de negócio.

🔗

App no ar (Streamlit Cloud)

Link público acessível. O professor testa gerando um orçamento real durante a avaliação.
