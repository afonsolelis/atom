Contexto

O Projeto: Imobiliária R.M

A Imobiliária R.M precisa automatizar a geração de orçamentos mensais de aluguel. Hoje, os corretores calculam tudo à mão — erros, retrabalho e tempo perdido.

  • Tipos de imóvel: Apartamento, Casa e Estúdio — cada um com valor base e regras próprias.
  • Acréscimos: quartos adicionais, vagas de garagem, taxa de contrato parcelável.
  • Desconto: 5% para apartamentos alugados por clientes sem crianças.
  • Exportação: orçamento anual em arquivo .csv com as 12 parcelas.
Objetivo: construir uma aplicação Python orientada a objetos que resolva esse problema do início ao fim.

Passo 1

Business Drivers

Antes de qualquer linha de código, entendemos por que o software existe:

Automação operacional

Eliminar cálculos manuais que geram erros e consomem tempo dos corretores.

Precisão financeira

Garantir exatidão matemática nos orçamentos — erro aqui impacta receita diretamente.

Digitalização comercial

Modernizar o processo de locação com propostas geradas em segundos.

Conformidade

Aplicar consistentemente todas as regras de contrato, descontos e acréscimos.

Passo 3 · SWEBOK 4.0

Requisitos Não Funcionais

Manutenibilidade

Código estruturado com OOP obrigatório — herança, encapsulamento, polimorfismo.

Interoperabilidade

Exportar .csv padrão, legível por Excel, Google Sheets e sistemas externos.

Usabilidade

Interface intuitiva para corretores gerar orçamentos sem treinamento técnico.

Confiabilidade

Exatidão matemática garantida — zero erro de arredondamento em cálculos monetários.

Desempenho

Geração de orçamento em menos de 2 segundos; suportar múltiplos usuários.

Segurança

Dados de clientes protegidos; validação de entradas; sem injeção de código.

Passo 5

Avaliando as Tecnologias

Com os requisitos claros, podemos agora escolher as ferramentas com critério:

🐍
Python
Linguagem principal. OOP nativa, bibliotecas ricas, sintaxe legível.
🗂️
csv (stdlib)
Exportação do orçamento anual. Zero dependência externa.
🔲
GitHub
Versionamento obrigatório. Entrega do código-fonte.
❓
Interface?
Terminal, HTML/CSS ou framework? Decidimos depois da arquitetura.
Tecnologia segue a arquitetura — nunca o contrário. A escolha final da interface vem na Aula 3.
