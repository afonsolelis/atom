Escala: do manual ao automático

CPU acima de 70%? O HPA cria Pods. Caiu a carga? Ele reduz. Entre 2 e 10 réplicas.

ConfigMap: configuração fora do código

Mesma imagem, ambientes diferentes — a config vem de fora (princípio 12-factor):

apiVersion: v1 kind: ConfigMap metadata: name: web-config data: APP_ENV: producao PAGE_SIZE: "20"

Injetado nos Pods como variáveis de ambiente ou arquivos — sem rebuildar a imagem.

Secret: dados sensíveis

apiVersion: v1 kind: Secret metadata: name: db-secret type: Opaque stringData: DB_PASSWORD: super-secreto
  • Tratados à parte, com permissões mais restritas que um ConfigMap.
  • Montados no Pod como variável de ambiente ou arquivo.
  • Nunca versione o valor real do Secret no Git.

Probes: o cluster sabe se o Pod está saudável

livenessProbe: # travou? reinicia o container httpGet: path: /health port: 80 readinessProbe: # ainda subindo? tira do tráfego httpGet: path: /ready port: 80

Liveness reinicia o que travou; readiness só manda tráfego pra quem está pronto.

Ingress: a porta de entrada

Um único ponto de entrada HTTP que roteia por host/caminho para vários Services:

apiVersion: networking.k8s.io/v1 kind: Ingress metadata: name: web spec: rules: - host: app.exemplo.com http: paths: - path: / pathType: Prefix backend: service: name: web port: number: 80

O quebra-cabeça completo

Um deploy de produção junta todas as peças que vimos:

  • Deployment + HPA → quantos Pods e como escalam.
  • ConfigMap + Secret → configuração e segredos injetados.
  • Probes → saúde e prontidão de cada Pod.
  • Service + Ingress → rede interna estável e entrada externa.
Tudo isso é texto declarativo versionado no Git: o cluster inteiro descrito em arquivos.

Mão na massa

Rolling update & rollback

Subir uma nova versão sem derrubar o sistema — e voltar atrás se der ruim:

$ kubectl set image deploy/web web=meu-app:2.0 # nova versão $ kubectl rollout status deploy/web # acompanha a troca $ kubectl rollout undo deploy/web # rollback imediato!

O Kubernetes troca os Pods aos poucos: o usuário nunca vê o site fora do ar.

Atividade prática

Deploy ponta a ponta de um app web

Deploy ponta a ponta de um app web, ao vivo:

  • Deployment com ConfigMap, Secret e probes.
