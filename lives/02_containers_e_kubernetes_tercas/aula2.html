Conteudo

Containers sao efemeros

  • Por padrao, tudo o que um container escreve vive dentro dele. Removeu o container → os dados se foram.
  • Otimo para a aplicacao (descartavel, recriavel a qualquer momento).
  • Pessimo para o banco de dados, uploads e qualquer estado que precisa durar.
  • Precisamos separar o dado do ciclo de vida do container.

Volumes: dados que sobrevivem

$ docker volume create dados-app $ docker run -d \ -v dados-app:/var/lib/postgresql/data \ -e POSTGRES_PASSWORD=senha \ postgres:16

Pode remover e recriar o container quantas vezes quiser: o volume dados-app mantem o banco intacto.

Conteudo

Bind mounts vs volumes

Volume (gerenciado)

O Docker controla onde fica. Ideal para dados de producao: bancos, arquivos persistentes.

Bind mount (pasta do host)

Mapeia uma pasta sua para dentro do container. Ideal para desenvolvimento: editar o codigo e ver refletir na hora.

Regra: volume para o que precisa durar; bind mount para o que voce esta editando.

Redes entre containers

$ docker network create minha-rede $ docker run -d --name db --network minha-rede postgres:16 $ docker run -d --name api --network minha-rede meu-app # dentro do container "api", o banco e alcancavel em db:5432

O nome do servico vira o "endereco" — base de tudo que vem a seguir.

Mao na massa

Subindo tudo com um comando

$ docker compose up -d # sobe db + api em segundo plano $ docker compose ps # status dos servicos $ docker compose logs -f # acompanha os logs $ docker compose down # derruba tudo (mantem o volume)

Um arquivo, um comando: qualquer pessoa sobe o ambiente identico ao seu.

Conteudo

Boas praticas com compose

  • .env: tire senhas e segredos do arquivo versionado.
  • depends_on + healthcheck: a api so sobe quando o banco esta pronto.
  • Named volumes: dados nomeados, faceis de inspecionar e fazer backup.
  • Nunca versione dados nem segredos no Git.
O compose.yaml e infraestrutura como codigo: seu ambiente vira texto, revisavel e reproduzivel.

Comparacao — compose vs K8s

Docker Compose vs kubectl

Conceito Docker Compose Kubernetes
Definicao do sistema docker-compose.yml manifests YAML (Deployment, Service)
Subir tudo docker compose up -d kubectl apply -f .
Ver status docker compose ps kubectl get pods
Ver logs docker compose logs -f api kubectl logs -f deploy/api
Parar/remover docker compose down kubectl delete -f .

Compose e para desenvolvimento local; kubectl e para producao em cluster.

Atividade pratica

Mao na massa: app + banco

Vamos montar, ao vivo, um app + banco com docker-compose:

  • Defina dois servicos: sua api e um postgres, na mesma rede.
  • Configure um volume nomeado para os dados do banco.
  • Suba com compose up, grave um registro, derrube e suba de novo.
  • Desafio: comprove que o dado sobreviveu a recriacao dos containers.
