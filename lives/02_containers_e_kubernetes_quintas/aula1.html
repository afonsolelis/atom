Conteudo

"Na minha maquina funciona"

  • O codigo roda no seu notebook, mas quebra no servidor. Por que?
  • Versoes diferentes de linguagem, bibliotecas e sistema operacional.
  • Variaveis de ambiente e dependencias instaladas "na mao".
  • Cada maquina e um floco de neve — unica e dificil de reproduzir.
Containers resolvem isso empacotando o app e todo o seu ambiente numa unidade que roda igual em qualquer lugar.

Conteudo

O que e um container

  • Um container e um processo isolado que carrega consigo tudo o que precisa para rodar: codigo, runtime, bibliotecas e configuracoes.
  • Compartilha o kernel do sistema hospedeiro — por isso e leve e rapido.
  • Isolado por namespaces e cgroups do Linux: cada container "acha" que tem o SO so pra ele.
  • Portavel: a mesma imagem roda no seu PC, no CI e na nuvem.

Container vs Maquina Virtual

Maquina Virtual Container
Virtualiza Hardware + SO completo So o processo — usa o kernel do host
Tamanho Gigabytes Megabytes
Inicializacao Minutos Segundos
Densidade Poucas por host Dezenas/centenas por host

Nao sao rivais: e comum rodar containers dentro de VMs na nuvem.

Imagem vs Container

Imagem = molde

Pacote imutavel com app + dependencias. E a "classe" — escrita uma vez, versionada e compartilhada.

Container = instancia

Uma imagem em execucao. E o "objeto" — voce cria varios da mesma imagem, cada um isolado.

Se voce fez a Live 01: e a mesma relacao entre classe e objeto.

Mao na massa

Primeiros comandos Docker

$ docker run -d -p 8080:80 nginx # baixa e roda o nginx $ docker ps # containers em execucao $ docker images # imagens locais $ docker logs <id> # ver a saida do container $ docker stop <id> # para o container $ docker rm <id> # remove o container

Abra http://localhost:8080 e veja o nginx respondendo de dentro do container.

Escrevendo um Dockerfile

FROM python:3.12-slim WORKDIR /app COPY requirements.txt . RUN pip install -r requirements.txt COPY . . CMD ["python", "app.py"]
$ docker build -t meu-app . # constroi a imagem $ docker run -p 5000:5000 meu-app

Conteudo

O ciclo de vida

  • Dockerfile (receita) → docker build →
  • Imagem (molde imutavel, versionavel) → docker run →
  • Container (instancia em execucao) → stop / rm.
A imagem pode ser publicada num registry (Docker Hub) e baixada por qualquer pessoa ou servidor — e assim que o app "viaja".

Atividade pratica

Mao na massa: empacotar um app

Vamos empacotar um app web simples (Flask ou Node) ao vivo:

  • Escreva um Dockerfile a partir de uma imagem base oficial.
  • Faca o build com uma tag e rode mapeando a porta com -p.
  • Acesse no navegador e veja seu app dentro do container.
  • Desafio: reduza o tamanho da imagem usando uma base slim/alpine.
