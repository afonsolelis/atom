Por que pensar antes de programar?

Código mal pensado é caro: bugs escondidos, horas de depuração e retrabalho. O pensamento computacional é a habilidade de formular um problema de forma que um computador — ou um humano — possa resolvê-lo.

  • Programar sem planejar é como construir sem planta.
  • O tempo gasto pensando reduz o tempo gasto consertando.
  • Pensamento computacional é uma habilidade geral — vale fora da programação também.

Os 4 pilares do pensamento computacional

Decomposição

Dividir o problema grande em partes menores e gerenciáveis.

Reconhecimento de padrões

Identificar semelhanças e repetições para reaproveitar soluções.

Abstração

Focar no que é essencial e ignorar detalhes irrelevantes.

Algoritmo

Definir uma sequência clara e finita de passos para resolver o problema.

Decomposição e reconhecimento de padrões

Decomposição: problema "calcular aprovação de uma turma" → calcular nota de um aluno → calcular média → comparar com limiar.

Padrões: se o cálculo de média funciona para um aluno, funciona para todos — basta virar uma função.

  • Decompor revela dependências ocultas entre partes do problema.
  • Padrões poupam código: escreva uma vez, use muitas vezes.
  • Toda refatoração começa reconhecendo código duplicado como um padrão.

Abstração: separar o essencial do ruído

Para calcular a média de notas, não importa o nome do aluno, a cor da caneta ou o ano. O que importa: a lista de notas e o limiar de aprovação.

  • Bons modelos abstraem o suficiente para resolver o problema sem informação desnecessária.
  • Abstrair demais torna o modelo inútil; de menos, o deixa inchado e frágil.
  • Em código: escolha bem os parâmetros de cada função — só o que ela realmente precisa.
Exemplo: media(notas) recebe somente a lista — não precisa saber quem é o aluno.

Mão na massa

Do pseudocódigo ao código Python

Pseudocódigo é o rascunho do algoritmo — linguagem humana com estrutura de código:

RECEBER lista de notas CALCULAR soma de todas as notas DIVIDIR soma pelo número de notas → média SE média >= 6,0 EXIBIR "Aprovado com média X" SENÃO EXIBIR "Reprovado com média X"

Sem preocupação com sintaxe — só com a lógica.

Mão na massa

Implementando em Python

def media(notas): return sum(notas) / len(notas) notas = [7.5, 6.0, 8.5, 5.0] m = media(notas) if m >= 6.0: print(f"Aprovado com média {m:.1f}") else: print(f"Reprovado com média {m:.1f}")

Notas [7.5, 6.0, 8.5, 5.0] → soma 27.0 → média 6.75 → Aprovado

Comparando linguagens · Python vs Rust

O mesmo algoritmo em Rust

fn media(notas: &[f64]) -> f64 { notas.iter().sum::<f64>() / notas.len() as f64 } fn main() { let notas = [7.5, 6.0, 8.5, 5.0]; let m = media(&notas); if m >= 6.0 { println!("Aprovado com média {:.1}", m); } else { println!("Reprovado com média {:.1}", m); } }

Mesma lógica, tipagem estática, zero garbage collector. Troque uma nota para 3,0 e observe o resultado.

Mãos à obra
