Conteúdo

Por que objetos?

Até agora, dados e funções viviam separados. Conforme o programa cresce, isso vira bagunça: dezenas de variáveis soltas e funções que recebem "tudo" como argumento.

  • Orientação a objetos junta, numa só unidade, os dados e o comportamento que age sobre eles.
  • Cada objeto representa uma "coisa" do problema: um aluno, uma conta, um produto.
  • Resultado: código mais organizado, próximo do mundo real e fácil de estender.

Conteúdo

__init__ e self, sem mistério

class Cachorro: def __init__(self, nome, raca): # roda ao criar o objeto self.nome = nome # self = o próprio objeto self.raca = raca # guarda os dados nele
  • __init__ é o construtor: executa automaticamente quando você faz Cachorro(...).
  • self é a referência ao objeto que está sendo criado — por isso aparece em todo método.
  • self.nome guarda o valor dentro daquele objeto específico.

Estado e comportamento

Os atributos guardam o estado; os métodos definem o comportamento que muda esse estado:

class Contador: def __init__(self): self.valor = 0 # estado def incrementar(self): # comportamento self.valor += 1 c = Contador() c.incrementar() c.incrementar() print(c.valor) # -> 2

Encapsulamento: proteger o estado

O objeto controla o acesso aos próprios dados — ninguém mexe no saldo "na unha":

class Conta: def __init__(self, saldo=0): self._saldo = saldo # _ = "não mexa direto" def depositar(self, valor): if valor > 0: self._saldo += valor def saldo(self): return self._saldo

As regras (não depositar valor negativo) ficam dentro do objeto.

Modelando o mundo real em código

Um truque para descobrir as classes a partir de uma descrição do problema:

  • Substantivos (aluno, conta, pedido) → viram classes.
  • Adjetivos / características (nome, saldo, status) → viram atributos.
  • Verbos (depositar, aprovar, calcular) → viram métodos.
"Um pedido tem itens e um valor total, e pode ser finalizado" já descreve uma classe inteira.

Comparando linguagens · Python vs Rust

Em Rust: struct + impl (sem herança, com precisão)

Rust não tem classes, mas struct + impl entregam estado + comportamento com garantias em tempo de compilação:

struct ContaBancaria { titular: String, saldo: f64, } impl ContaBancaria { fn nova(titular: &str, saldo_inicial: f64) -> Self { Self { titular: titular.to_string(), saldo: saldo_inicial } } fn depositar(&mut self, valor: f64) { self.saldo += valor; } fn sacar(&mut self, valor: f64) -> bool { if valor <= self.saldo { self.saldo -= valor; true } else { false } } }

struct = atributos; impl = métodos. O compilador garante que ninguém acessa saldo diretamente — encapsulamento por design, não por convenção.

Recapitulando

Pontos-chave

Classe e objeto

Classe é o molde; objeto é a instância criada a partir dele.

__init__ e self

O construtor inicializa o objeto; self é a referência a ele próprio.

Estado + comportamento

Atributos guardam dados; métodos agem sobre esses dados.

Encapsulamento

O objeto protege seu estado e expõe só o que faz sentido usar.
